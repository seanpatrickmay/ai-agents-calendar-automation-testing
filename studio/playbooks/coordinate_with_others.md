# Playbook: Events that depend on other people

Examples: "meeting with the instructor, week of Oct 26", "team sync",
"someone asks if you're free Thursday".

You can't know the other person's availability, so you never create the
meeting yourself. You make it *easy for the user* to set it up.

## Steps
1. Create a `pending` **task**: "Schedule <meeting> with <person>", due a
   few business days before the window opens (or within 1 day if replying
   to someone).
2. Find 3–5 candidate slots from the user's free/busy that fit the window
   and working hours. Prefer the other person's known office hours if listed
   in `contacts.md` or on a course Staff page.
3. Draft an email/message into the proposal's `drafts` section. Short,
   specific, with the candidate slots. The user sends it.
4. Optionally propose **tentative holds** on those slots (title prefixed
   `HOLD?`), only if the user has approved holds before.
5. When a reply arrives with a confirmed time, propose the real event and
   the removal of holds.

## Teams
- Team deadlines: propose a team-internal deadline 24–48 h before the real
  one (for review), flagged as a suggestion.
- Never add teammates as attendees without approval.
